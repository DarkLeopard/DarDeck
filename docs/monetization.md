# DarDeck: воронка продаж и монетизация

Бизнес-документ. Описывает путь пользователя от первого контакта до платящего
клиента и источники выручки. Опирается на архитектуру из README: движок,
серверная политика выдачи, плагины БД и правил, боты-темы, UGC.

## 1. Продукт и ценность

Карточки-фанты для пар: раз в день каждый участник получает задание, как
порадовать партнёра. Ключевые свойства, которые продаём:

- регулярный («ежедневный») сценарий — естественный повод для подписки;
- персонализация через плагины правил (категории, ротация, ограничения пары);
- UGC: свои карточки, приватные и публичные — удержание без затрат на контент;
- разные тематики = разные боты поверх одного движка — низкая стоимость
  запуска новой аудитории.

## 2. Воронка

### 2.1. Осведомлённость (Awareness)

- Telegram-боты в тематических каналах и каталогах ботов (@BotFather,
  BotoStore, подборки «боты для пар»).
- Первая отладочная тематика — BDSM-пак (сильная ниша, слабая конкуренция,
  готовое ядро карточек из koloda).
- Публичные карточки пользователей как органический контент: автор делится
  своей карточкой → у каждого, кто её видит, ссылка на бота.
- Веб-интерфейс (landing / примеры карточек) — точка входа из поиска.

### 2.2. Активация (Activation)

- Бот без регистрации: /start → пара выбирает тематику → обе стороны
  подтверждают связь (инвайт партнёра) → первая карточка в день подключения.
- Метрика активации: пара получила и выполнила первую карточку до конца дня D0.
- Онбординг-серия: 3 карточки из лучшего пула, затем — серверное расписание.

### 2.3. Удержание (Retention)

- Ежедневный пуш-ритуал от самого бота; streak / история выполненных фантов.
- Отзывы и рейтинг карточек (ядро движка) — качество пула растёт, отток падает.
- UGC-мотивация: 10 лайков на публичную карточку → +1 день премиума автору —
  бесплатный способ удержания «творцов».
- Полуавтоматическая чистка слабых карточек защищает от «пула протух».

### 2.4. Конверсия в оплату (Revenue)

Точки апселла — моменты боли free-пользователя:

1. Лимит частоты: free — жёсткий серверный интервал (например, 1 карточка
   в сутки, без выбора времени); премиум-месседж показывается, когда пара
   явно «просит ещё» (попытка получить карточку раньше интервала).
2. Лимит количества на день: free — 1, premium — сколько захотят.
3. Категории: часть категорий пула закрыта для free (превью с замком).
4. История и статистика пары (рейтинг, архив выполненных фантов) — premium.
5. Экспериментальные тематики/паки — premium-доступ.

Метрики: конверсия free→premium по каждой точке (события сервера:
`limit_hit_premium_prompt` → `premium_page_open` → `payment_done`).

### 2.5. Монетизация возвратов (Win-back / реактивация)

- Бот пишет в «спящий» период пары: «ваша пара не выполняла фанты N дней».
- Повторная активация по промокоду (даётся и рекламным партнёрам).

## 3. Модель монетизации

### 3.1. Premium-подписка (основной источник)

| Тариф | Что даёт | Цена (ориентир) |
|---|---|---|
| Free | 1 карточка/сутки, фиксированный интервал, базовые категории | 0 |
| Premium | свободная частота и количество, все категории, история, приоритет выдачи | ~199 ₽/мес или ~1490 ₽/год |
| Premium Duo | на пару целиком (обе стороны получают премиум-права) | x1.5 от Premium |

Пара — естественная единица продажи: платит один, пользуется двое.
Сервер решает (политика выдачи на стороне сервера), что даёт тариф, —
обход невозможен.

### 3.2. Нативная реклама (спонсорские карточки)

- Карточка-фант, где действие совпадает с продуктом рекламодателя:
  «подари цветы» → доставка цветов; «устрани вечер» → доставка еды;
  «выйдите вдвоём» → билеты/кино.
- Рекламодатель = источник реального действия, полезного паре. Баннеров нет.
- Ограничения (по README): не чаще 1 брендированной карточки на N дней;
  рекламная карточка всегда помечена; учёт рекламных конверсий уже есть
  в статистике движка — отдаём рекламодателю честный отчёт (клики →
  выполненные действия).
- Модель оплаты: CPA за выполненное действие (заказ/переход) с фикс-минимумом;
  для первой продажи — спонсорство тематики целиком («пак поддержан X»).

### 3.3. Донаты и платные карточки авторов

- Донаты напрямую автору публичной карточки (кнопка «поддержать автора»
  в описании карточки; платформа берёт комиссию 10–20%).
- В перспективе: авторская продажа своих паков через движок (плагин БД
  позволяет подключить сторонний источник), ревшара платформе.
- Это делает UGC самоподдерживающимся: качественные авторы остаются.

### 3.4. Анти-модели (что не делаем)

- Никаких баннеров, попапов и interstitial — убивает ритуал.
- Никакой продажи чувствительных данных пары.
- Паки чувствительной тематики не публикуем в открытом виде (правила
  приватности README), монетизируем через приватную продажу доступа.

## 4. Юнит-экономика (черновик)

Считаем на пару:

- CAC — канал: каталоги ботов и орг. UGC-распространение ≈ дёшево; платный
  трафик — только после подтверждения конверсии free→premium.
- ARPPU = подписка + доля рекламных CPА на пару.
- Ключевые отношения: LTV/subscription ~ срок жизни пары × конверсия в
  premium. Удержание (раздел 2.3) важнее трафика: продукт ежедневный,
  месяцы жизни дают основную выручку.
- Правило запуска канала: платим за трафик, только если
  CAC < (доля премиум × ARPPU × срок жизни).

## 5. Этапы запуска монетизации

1. **MVP (отладка на BDSM-паке)**: только free, замер ретеншена и D7,
   инструментирование событий воронки в движке.
2. **Премиум**: тарифы по 3.1, точки апселла по 2.4, приём платежей
   (Telegram Stars / ЮKassa), A/B интервалов.
3. **Реклама**: 1–2 пилотных CPA-партнёра (цветы/еда), отчёт по конверсиям
   из статистики движка, проверка влияния на ретеншен.
4. **UGC-экономика**: донаты авторам, рейтинг авторов, продажа паков.
5. **Масштабирование**: новые тематики-боты поверх того же движка,
   каждая — свой канал и свой спонсор.

## 6. Сводка событий воронки (для инструментирования)

Движок уже ведёт статистику; минимальный набор событий:

- `bot_started` (осведомлённость → активация)
- `pair_linked` (пара создана)
- `first_card_done` (активация выполнена)
- `card_done` / `card_rated` (удержание)
- `ugc_card_created` / `ugc_card_10_likes` (UGC-экономика)
- `limit_hit_premium_prompt` (точка боли free)
- `premium_page_open` / `payment_done` (конверсия)
- `sponsor_conversion` (рекламные действия)
