# Delight

Движок ежедневных карточек-фантов для пар. Каждый участник раз в день получает
карточку с заданием — способом порадовать свою вторую половинку.

## Архитектура

Движок отделён от контента и правил:

- **Движок (ядро)**:
  - выдача карточек по настраиваемому расписанию;
  - учёт выполнений (статистика: карточки, отзывы, рекламные конверсии);
  - учёт уже показанных карточек — без повторений, повторная выдача только
    по явному правилу;
  - рейтинг и отзывы на карточки; полуавтоматическая чистка слабых карточек
    (низкий рейтинг, жалобы) с ручным подтверждением.
- **Политика выдачи (сервер решает)**: частота и количество карточек
  регулируются на стороне сервера. Сервер может отдать юзеру право настройки
  (premium) или оставить жёсткий серверный интервал (free).
- **Плагин БД**: хранилище карточек на тематику (адаптер — любая база/источник).
- **Плагин правил выдачи**: как выбирать карточку (случайно, по категориям,
  ротация, ограничения пары, донат/премиум-приоритет).
- **Боты**: телеграм-боты разной тематики поверх одного движка; веб-интерфейс
  для управления карточками.
- **Картинки**: обложки карточек генерируются локальной моделью (первая).
- **UGC (бесплатный функционал)**: пользователь может создавать свои карточки —
  приватные (только для своей пары) или публичные. В настройках галочка
  «видеть публичные карточки других людей». Карточка, набравшая 10 лайков
  и ни одного дизлайка, автоматически добавляется в пул соответствующей
  тематики. Вознаграждение автора: 10 лайков на публичную карточку → +1
  бесплатный день премиума. Пост-модерация: жалобы могут исключить карточку
  из пула и после публикации; автофильтр отсекает спам. Антифарм: лайк
  может поставить только тот, кому карточка реально выдалась.

## Монетизация

1. Premium: пользователь сам регулирует, сколько карточек и с какой
   периодичностью получает.
2. Нативная реклама в карточке: «фант: подари цветы» → спонсор доставки цветов.
   Рекламодатель = источник реального действия, полезного паре.
3. Донаты напрямую автору.
Реклама ограничена: не чаще N карточек с брендом, без навязчивых баннеров.

## Приватность / контент

Публичный репозиторий содержит только код и нейтральные ассеты. В git и на
GitHub никогда не попадает:

- базы-паки карточек с чувствительной тематикой (в т.ч. BDSM-контент);
- сгенерированные изображения для таких пакетов;
- токены, ключи, пользовательские данные.

Паки хранятся локально/в приватных хранилищах и подключаются к движку
конфигом; их пути — вне репозитория.

## Состав репозитория (план)

- `engine/` — ядро движка
- `adapters/db/…` — адаптеры хранилищ
- `adapters/rules/…` — наборы правил выдачи
- `bots/telegram/…` — боты-темы
- `web/…` — веб-интерфейс управления карточками
- `tools/…` — обработка отзывов, чистка карточек, генерация картинок
- `docs/` — схемы, дизайн правил, партнёрство/реклама
